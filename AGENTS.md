# Контекст MacroDashboard

## Назначение и архитектура

Это Python-приложение на Streamlit: сводка макроэкономических показателей,
экономический календарь, ставки центральных банков и новости. Интерфейс и
документация преимущественно на русском. Постоянное хранилище — локальная SQLite;
отдельного API-сервера и frontend-сборки нет.

Основной поток: `src/fetch_*.py` → `scheduler.py` → `src/storage.py` →
`data/macro.db` → `src/build_summary.py` → `app.py`.

| Файл | Ответственность |
| --- | --- |
| `app.py` | Streamlit-интерфейс, выбор периода, подсветка изменений, экспорты Excel/HTML/PDF, календарь и новости |
| `scheduler.py` | Ручной CLI обновления: группы источников, вызов fetch/save, обработка ошибок отдельных шагов |
| `config.py` | Пути, загрузка `.env`, ключи API, списки стран/индикаторов, RSS и диапазон календаря |
| `src/storage.py` | Сохранение и чтение таблиц SQLite, очистка таблиц |
| `src/build_summary.py` | Сводка по 17 странам, выбор источников и периодов, годовые значения IMF как fallback |
| `src/snapshot.py` | Недельные снимки сводки и сравнение с предыдущей неделей |
| `src/charts.py` | Графики Plotly |
| `src/fetch_*.py` | Получение и нормализация данных; подробная карта в `src/AGENTS.md` |
| `test.py` | Ручная диагностика загрузки ставок с печатью результата; это не автоматический тест |
| `src/fetch_worldbank.py` | Пустая заготовка, пока не используется |
| `README.md`, `SOURCES.md` | Пользовательская инструкция и описание источников; сверять с кодом при изменениях |

`scheduler.py` не является постоянно работающим сервисом расписания: обновление
происходит при его запуске. Частичная загрузка не обновляет недельный снимок;
полный запуск вызывает `save_weekly_snapshot()` после всех групп.

## Запуск

Запускать команды из корня проекта. Код использует синтаксис Python 3.10+;
ранее локальное окружение работало на Python 3.12.

```text
python -m venv .venv
python -m pip install -r requirements.txt
```

Вторую команду выполнять после активации `.venv` либо через её Python.
На Windows активация: `.venv\Scripts\Activate.ps1`; на Linux/WSL:
`source .venv/bin/activate`.

Скопировать `.env.example` в `.env` и заполнить `FRED_API_KEY`, `ESTAT_APP_ID`,
`BEA_API_KEY`, либо задать эти переменные в окружении. Не выводить значения ключей
в ответы, логи, документацию и коммиты.

```text
python scheduler.py --list
python scheduler.py --help
python scheduler.py us
python scheduler.py cn us
python scheduler.py
streamlit run app.py
```

Использовать фактические ключи `GROUPS` (`cn`, а не `china`): примеры в docstring
планировщика могут отставать от реализации. Даже `--help` импортирует загрузчики
и требует установленных зависимостей. Загрузка обращается к внешним сервисам,
может быть медленной и зависит от доступности сети и ключей.

## Данные и зависимости

- Приватные данные и ключи хранить в файлах или каталогах, исключённых через
  `.gitignore`. При добавлении новых приватных файлов добавлять соответствующие
  правила и проверять, что файлы не находятся в индексе Git: `.gitignore` не
  исключает уже отслеживаемые файлы. В шаблонах оставлять только пустые значения.
- `config.py` создаёт `data/` уже при импорте; SQLite создаётся при подключении,
  NIFD скачивает PDF в `data/nifd_reports/`.
- Зависимости перечислены в `requirements.txt` без закреплённых версий.
  Настроенного набора автоматических тестов в текущем дереве нет.

## Правила работы

- До удаления «неиспользуемого» файла проверять импорты, косвенные вызовы,
  CLI-точки входа и документацию.
- Менять только необходимое для задачи; сохранять язык интерфейса и UTF-8.
  Не переписывать весь файл ради переводов строк или форматирования.
- Предпочитать первичные источники макроданных. Существующие RSS и ForexFactory
  обслуживают новости и календарь; не удалять их из-за общих требований к
  источникам макростатистики. Для смены источника сверять `SOURCES.md` и код.
- Не заменять отсутствующие данные нулями, не смешивать проценты, абсолютные
  суммы, квартальные/годовые периоды, YoY/MoM и сезонную корректировку.
- Изменение показателя проверять по всей цепочке: fetch → схема storage →
  summary → UI → snapshot, если показатель участвует в подсветке.
- Полный сетевой запуск не использовать как обязательный тест небольшой правки.
  Для парсеров и расчётов проверять репрезентативные локальные примеры; для
  интерфейса — запуск и отображение при доступном окружении. Сообщать, какие
  проверки фактически выполнены и что осталось непроверенным.
- Синтаксис можно проверить через `ast.parse` без импортов и создания кэша;
  это не подтверждает корректность внешних API или расчётов.

При изменении архитектуры, способов запуска или контрактов данных обновлять
соответствующий `AGENTS.md`; не записывать сюда секреты и временные логи задач.
