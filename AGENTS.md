# Macro Dashboard — ввод для разработчика и ИИ-агента

**Актуально на 26 октября 2026 года.** Этот документ относится к **рабочему проекту Macro Dashboard**, а не к отдельному хакатону. Прочитай `README.md`, `INSTRUCTIONS.md`, `SOURCES.md`, `AUDIT.md` перед существенными изменениями.

## 1. Назначение и состояние

Macro Dashboard — локальное Python/Streamlit-приложение с SQLite для просмотра и обновления макроэкономических данных **18 экономик**, включая еврозону и Россию. Включает сводку по макрометрикам, выбор периода, исторические ряды, расширенные российские показатели, недельные сравнения, экспорт, RSS и экономический календарь.

На 26.10.2026 **основные компоненты работают, но не все внешние источники стабильно доступны**. Полный `scheduler.py` завершился результатом `53 OK / 1 PARTIAL / 3 EMPTY / 2 ERROR` (код `2`). Это не означает, что приложение полностью отказало; детали — `AUDIT.md`. Нельзя утверждать, что каждый ряд независимо сверен с первоисточником.

## 2. Архитектура

```text
config.py / .env
      ↓
scheduler.py → src/fetch_*.py и src/Russia/*.py
      ↓
 src/storage.py → SQLite по config.DB_PATH
      ↓
 src/build_summary.py → app.py (Streamlit)
                    ↘ src/snapshot.py, src/charts.py, экспорты
```

| Файл / папка | Ответственность |
|---|---|
| `config.py` | `BASE_DIR`, `DATA_DIR`, `DB_PATH`, ключи FRED/BEA/e-Stat, RSS |
| `scheduler.py` | Группы обновления, функции fetch/save, статусы этапов, коды выхода, снимок после полного успеха |
| `src/fetch_*.py` | Страновые и глобальные загрузчики; парсинг API, HTML, XLSX, PDF |
| `src/Russia/` | Отдельные детальные ряды России: кредиты, ставки, ипотека, деньги, торговля, MOEX, ИИС/ПИФ, RUONIA |
| `src/storage.py` | Валидация бизнес-ключей, транзакции SQLite, merge с сохранением истории |
| `src/build_summary.py` | Сборка сводки, выбор данных по месяцу/году, приоритеты источников и методологические подписи |
| `app.py` | Интерфейс, фильтры, подсветка, графики, экспорты, календарь и новости |
| `src/snapshot.py` | Недельные снимки и сравнение |
| `scripts/import_bbg.ps1` | Перемещение ручной Excel-выгрузки Bloomberg в `data/bloomberg/`; локальные пути требуют настройки |
| `test.py` | **Временный одноразовый диагностический скрипт.** Каждый новый тест полностью заменяет его содержимое |

Не называй весь проект `macro.db`: это имя файла базы в рассмотренной конфигурации. При работе с базой **всегда используй `config.DB_PATH`**, не жёстко заданное имя.

## 3. Быстрый запуск и команды

После установки зависимостей и настройки `.env` (порядок — `README.md`):

```powershell
python scheduler.py --list
python scheduler.py --dry-run
python scheduler.py --dry-run ru
python scheduler.py ru_reference
python scheduler.py ru_ruonia
python scheduler.py fred
python scheduler.py cn
python scheduler.py ca
python scheduler.py          # полный запуск, 59 шагов
streamlit run app.py
```

Основных групп — 19: `bbg rates us sg br gb jp kr au ca ch cn in tr ru fred imf eurostat extra`. Дополнительные выборочные группы — `ru_reference`, `ru_ruonia`; они включены в полную группу `ru` и не удваивают полный запуск. Название группы Китая — `cn`, **не `china`**. Полный список и коды завершения — `INSTRUCTIONS.md`.

Перед любым изменением `scheduler.py` сначала проверь `--dry-run`; не запускай все источники ради теста одного загрузчика. Сеть может возвращать SSL, тайм-ауты и 403 независимо от корректности Python.

## 4. Неприкосновенные методологические договорённости

1. **Не переделывай автоматически формулы и источники отношений к ВВП.** Они отдельно согласовывались; безопасность кода ≠ повод переписывать экономическую методологию.
2. Приоритет — опубликованный национальный/официальный ряд, затем согласованный международный источник. Реальные вынужденные исключения (NIFD, Tonghuashun, chinadata.live, отдельные Bloomberg Excel) документированы в `SOURCES.md`. Не удаляй их лишь потому, что это не идеальное API.
3. **Не вычисляй новые макропоказатели из других рядов самовольно** и не заменяй одни определения другими. Любая новая расчётная формула требует явного решения владельца, источников, единиц измерения и проверки.
4. Не смешивай **Central / Federal / General Government**, торговлю товарами и **Current Account**, квартальные и годовые факты, **SA/NSA**, YoY/MoM, валюты, абсолютные значения и доли ВВП.
5. Сохраняй период и статус в ячейке. IMF WEO как годовой резерв за текущий/будущий год — с пометкой **«прогноз; годовое»**; за завершённый год — опубликованное годовое историческое значение без безусловной маркировки прогноза. Не выдавай годовой WEO за квартальный факт.
6. Принятое правило сводки: **декабрь → годовое значение**, другие месяцы — квартальное там, где это предусмотрено текущей методологией. Не меняй без отдельного решения.
7. Не подставляй `0` вместо недоступного значения или прочерка, не превращай предварительные данные в окончательные. Сохраняй актуальную дату публикации/наблюдения, а не дату запуска скрипта.
8. Для России допускается история **с 2020 года**, если официально доступна; не обрезай её ради косметики. Bloomberg ручной и ограниченный, не автоматизируй «из воздуха».

## 5. Обязательные правила изменений и качества

- Сначала прочитай актуальный файл, затронутые импорты, `storage.py` и `build_summary.py`; не работай по устаревшей копии вместо текущей. При выдаче изменений предпочтителен **полный файл для замены**, а не архив из неясных патчей.
- Меняй **только область задачи**. Не переписывай целые парсеры ради косметического рефакторинга. Не зови внешних людей для выполнения пользовательских действий: работа выполняется владельцем локально.
- Перед правкой SQLite делай согласованную резервную копию через `sqlite3.Connection.backup()`. При чтении — `mode=ro`. Сохранение должно проверять ключи, не удалять старые даты из-за частичного ответа, выполнять rollback при исключениях и не смешивать страны.
- Пустой или частичный API-ответ должен приводить к `EMPTY`/`PARTIAL`/`ERROR`, а не к ложному `OK`. Не выдавать завершение одного шага за полностью успешный полный планировщик.
- Ключи только в `.env`/переменных окружения. Никогда не печатай секреты, полный URL с токенами, личные пути/резервные SQLite в публичные документы. Проверяй `.gitignore` **и `git ls-files`**, так как `.gitignore` не удаляет уже отслеживаемые файлы.
- Не отключай TLS-проверку без осознанного, узко ограниченного исключения. Известное временное исключение для **Росстата и Казначейства** в `src/fetch_russia.py` существует из-за недоверенной цепочки на проверенном Windows; оно **остаётся риском** и должно быть зафиксировано, но не повод менять остальные источники.
- Экспорт HTML/PDF/RSS экранировать; Excel/CSV защищать от формульных инъекций. Не допускать возврата небезопасного экспорта.
- После изменений: `python -m compileall -q app.py src`, `python scheduler.py --dry-run [группа]`, целевой тест/запуск, `sqlite PRAGMA quick_check`, а при изменении UI — проверка Streamlit и экспорта. Сообщай, **что действительно проверено**, а что не проверено вживую.
- При изменении API/команд — обнови `README.md`/`INSTRUCTIONS.md`; при изменении источника — `SOURCES.md`; при исправлении риска — `AUDIT.md`. Не подменяй результат теста ожиданием.

## 6. Известные ограничения — не «исправлять» вслепую

- **StatCan:** на 26.10.2026 квартальный API выдавал `SSLError`, CPI — timeout. Последняя сохранённая история осталась доступна. Не обнуляй данные.
- **Китай Core CPI:** исправлен поиск второй страницы NBS; тест нашёл сентябрь 2026 = 1.0% YoY. Вынужденные NIFD/Tonghuashun и поисковые HTML-механизмы — осознанные решения.
- **LPR Китая:** `SSLError`; **Япония FRED ставка:** timeout, при этом альтернативный BoJ-ряд загрузился.
- **ForexFactory:** HTTP 403, RSS продолжает работать; не путать отказ календаря с падением приложения.
- **Турция CPI:** сетевой timeout. **RUONIA:** отдельно был timeout за 2024 год; сохранение общей истории не является доказательством, что 2024 год загружен заново без пропусков.
- `requirements.txt` не закрепляет версии. Работа в другом окружении может потребовать адаптации, но не повод автоматически обновлять все зависимости.

## 7. Отношение к отдельному хакатону

В исторических файлах может встречаться контекст хакатона. **Он не задаёт задачи и архитектуру рабочего Macro Dashboard.** Здесь один владелец/исполнитель; не создавай фиктивную «команду», не переноси требования хакатона в рабочий код без явного запроса. Приоритет — стабильность текущего приложения и данных.

**Базовое правило:** лучше небольшое проверенное изменение с сохранением данных, чем крупная переделка работающей системы.

Регрессионные проверки: `python -m unittest discover -s tests -v`; постоянные тесты находятся в `tests/`, а не в диагностическом `test.py`.

## Контейнерная эксплуатация

Точки входа остаются в корне. `scripts/`, `deploy/`, `docs/`, `.github/` и `tests/`
содержат инструкции для своих каталогов; перед правками читать их `AGENTS.md`.
Карта проекта — `docs/ARCHITECTURE.md`, деплой — `docs/DEPLOYMENT.md`.
`MACRO_DATA_DIR` задаёт каталог SQLite и PDF NIFD; по умолчанию `data/` проекта.
Контейнеры web/updater используют `/app/data` и UID/GID 10001. Образ устанавливает
`requirements.lock` и Chromium в `/opt/playwright` для PDF-экспорта.
Новые зависимости согласовывать между `requirements.txt`, lock-файлом и Dockerfile.
PR запускает offline-проверки; push master публикует и выкладывает проверенный образ.
