# MacroDashboard — контекст и инициативы (хакатон)

Этот документ — для LLM-ассистента, который помогает команде хакатона. Прочитай его полностью перед тем, как что-то
объяснять команде или писать код. В документе — контекст рабочего проекта (часть I) и направления расширения под
хакатон (часть II). Твоя задача — **объяснять команде, что делать, и писать код под их контролем**, не ломая
существующее.

---

## Часть I. Контекст рабочего проекта

### Назначение и архитектура

Python-приложение на Streamlit: сводка макроэкономических показателей, экономический календарь, ставки центральных
банков и новости. Интерфейс и документация на русском. Постоянное хранилище — локальная SQLite. Отдельного API-сервера и
frontend-сборки нет.

Основной
поток: `src/fetch_*.py` → `scheduler.py` → `src/storage.py` → `data/macro.db` → `src/build_summary.py` → `app.py`.

| Файл                      | Ответственность                                                                                       |
|---------------------------|-------------------------------------------------------------------------------------------------------|
| `app.py`                  | Streamlit-интерфейс, выбор периода, подсветка изменений, экспорты Excel/HTML/PDF, календарь и новости |
| `scheduler.py`            | Ручной CLI обновления: группы источников, вызов fetch/save, обработка ошибок отдельных шагов          |
| `config.py`               | Пути, загрузка `.env`, ключи API, списки стран/индикаторов, RSS и диапазон календаря                  |
| `src/storage.py`          | Сохранение и чтение таблиц SQLite, очистка таблиц                                                     |
| `src/build_summary.py`    | Сводка по 17 странам, выбор источников и периодов, годовые значения IMF как fallback                  |
| `src/snapshot.py`         | Недельные снимки сводки и сравнение с предыдущей неделей                                              |
| `src/charts.py`           | Графики Plotly                                                                                        |
| `src/fetch_*.py`          | Получение и нормализация данных; подробная карта в `src/AGENTS.md`                                    |
| `test.py`                 | Ручная диагностика; это не автотест                                                                   |
| `src/fetch_worldbank.py`  | Пустая заготовка                                                                                      |
| `README.md`, `SOURCES.md` | Пользовательская инструкция и описание источников                                                     |

`scheduler.py` — не постоянно работающий сервис: обновление происходит при запуске. Частичная загрузка не обновляет
недельный снимок; полный запуск вызывает `save_weekly_snapshot()` после всех групп.

### Запуск

Из корня проекта. Python 3.10+, локально работало на 3.12.

```text
python -m venv .venv
python -m pip install -r requirements.txt
```

Активация: `.venv\Scripts\Activate.ps1` (Windows) или `source .venv/bin/activate` (Linux/WSL).

Скопировать `.env.example` в `.env` и заполнить `FRED_API_KEY`, `ESTAT_APP_ID`, `BEA_API_KEY`. Не выводить значения
ключей в ответы, логи, документацию и коммиты.

```text
python scheduler.py --list
python scheduler.py --help
python scheduler.py us
python scheduler.py cn us
python scheduler.py
streamlit run app.py
```

Ключи `GROUPS` — фактические (`cn`, а не `china`). Примеры в docstring планировщика могут отставать от реализации.
Даже `--help` импортирует загрузчики и требует установленных зависимостей. Загрузка обращается к внешним сервисам, может
быть медленной и зависит от сети и ключей.

### Данные и зависимости

- Приватные данные и ключи — в файлах/каталогах, исключённых через `.gitignore`. При добавлении новых —
  обновлять `.gitignore` и проверять, что файлы не в индексе Git. В шаблонах — только пустые значения.
- `config.py` создаёт `data/` при импорте; SQLite создаётся при подключении; NIFD качает PDF в `data/nifd_reports/`.
- Зависимости — в `requirements.txt` без закреплённых версий. Автотестов в дереве нет.

### Правила работы с рабочим проектом

- До удаления «неиспользуемого» файла — проверять импорты, косвенные вызовы, CLI-точки входа, документацию.
- Менять только необходимое; сохранять язык интерфейса и UTF-8. Не переписывать файл ради форматирования.
- Предпочитать первичные источники макроданных. RSS и ForexFactory обслуживают новости и календарь — не удалять их из-за
  общих требований к источникам макростатистики. Для смены источника сверять `SOURCES.md` и код.
- Не заменять отсутствующие данные нулями, не смешивать проценты, абсолютные суммы, квартальные/годовые периоды, YoY/MoM
  и сезонную корректировку.
- Изменение показателя проверять по всей цепочке: fetch → схема storage → summary → UI → snapshot, если показатель
  участвует в подсветке.
- Полный сетевой запуск — не обязательный тест небольшой правки. Для парсеров проверять локальные примеры; для
  интерфейса — запуск и отображение. Сообщать, какие проверки фактически выполнены, что осталось непроверенным.
- Синтаксис можно проверить через `ast.parse` без импортов и кэша; это не подтверждает корректность внешних API или
  расчётов.

При изменении архитектуры, способов запуска или контрактов данных обновлять `AGENTS.md`; не записывать туда секреты и
временные логи.

## Часть II. Хакатон: направления расширения

### Как пользоваться этой частью

Команда хакатона расширяет рабочий проект новым функционалом. Задача — **не сломать существующее** и **показать сильный
MVP на защите**. Жёсткого распределения задач и сроков нет: каждый берёт то, что ему интересно. Твой (LLM) вклад —
объяснять, разбивать работу на шаги, писать код, предупреждать о рисках.

### Цель MVP

Расширить дашборд до **презентабельного MVP** с фокусом на **одну страну — Россию**.

- Данные по РФ — **открытые, официальные, легко доступные** (Росстат, ЦБ, Минфин, ЕМИСС, MOEX).
- Показываем **весь функционал** на одной стране: метрики, графики, лента, фильтры, экспорт.
- На защите: «Россия — полностью, остальные 16 стран — в разработке, интерфейс готов».

**Не трогаем:** основную сводную таблицу (`app.py`, первая вкладка), 16 других стран, BBG-выгрузку.

**Делаем:** новую вкладку «Россия» + максимум метрик по ней.

### Зоны, чтобы не мешать друг другу

**🟢 Ядро — лидер проекта.** `app.py` (основная
таблица), `build_summary.py`, `scheduler.py`, `storage.py`, `snapshot.py`, все `src/fetch_*` для 17 стран. Без
согласования не трогаем. Расширения — только новыми модулями и новой вкладкой.

**🟡 Россия — основная площадка команды.** Новая папка `src/russia/`:

```
src/russia/
├── __init__.py
├── fetch_russia_macro.py          # макро (ВВП, инфляция, безработица, ставка)
├── fetch_russia_budget.py         # Минфин: ОФЗ, займы, дефицит, ФНБ
├── fetch_russia_basket.py         # потребительская корзина (Росстат/ЕМИСС)
├── fetch_russia_market.py         # MOEX: IMOEX, RTS, OFZ, ключевые акции
├── fetch_russia_news.py           # лента новостей с агрегацией
└── build_russia_summary.py        # сборка страноведческой сводки
```

Новые вкладки в `app.py` добавляет **один человек** (лидер фронта). Остальные в `app.py` не лезут — только свои модули.

**🔴 Дизайн — отдельное направление.** Тема Streamlit, CSS, типографика, цвета, иконки. Работает с `app.py` **в части
стилей**, не трогая логику.

### Принцип достоверности источников — критично

Это главное правило проекта. На защите источник важнее красоты и количества метрик.

**Разрешено (первоисточники):**

| Источник   | Что даёт                                                              | URL                        |
|------------|-----------------------------------------------------------------------|----------------------------|
| Росстат    | ВВП, инфляция, безработица, промпроизводство, потребительская корзина | rosstat.gov.ru, fedstat.ru |
| ЕМИСС      | Агрегатор Росстата в машиночитаемом виде                              | fedstat.ru                 |
| ЦБ РФ      | Ключевая ставка, курсы, банковская статистика                         | cbr.ru                     |
| Минфин РФ  | ОФЗ, госдолг, дефицит, ФНБ                                            | minfin.gov.ru              |
| MOEX       | Котировки, индексы, объёмы (ISS API)                                  | iss.moex.com               |
| ЕАБР / ЕЭК | Аналитика и данные по ЕАЭС                                            | eabr.org                   |
| FRED       | Готовые серии по РФ                                                   | fred.stlouisfed.org        |

**Запрещено:** агрегаторы без первоисточника (Trading Economics, CEIC, РБК-Котировки, БКС-Экспресс), Telegram-каналы,
форумы, любые вторичные сайты для расчётных показателей.

**Расчётные показатели** (Долг/ВВП, Реальный ВВП на душу, инфляция в годовом выражении) — **только считать самим из
первоисточников**. В коде видно: источники исходных данных + формула + пометка `(расчёт: Росстат + ЦБ)`.

### Направления работы (без жёстких сроков)

**Макро (`fetch_russia_macro.py`).** ВВП (квартальный, номинальный и реальный), инфляция (YoY и MoM), ключевая ставка,
безработица, промпроизводство, реальные располагаемые доходы, оборот розничной торговли. Основной источник — ЕМИСС API (
SDMX/JSON/CSV).

**Бюджет и долг (`fetch_russia_budget.py`).** Госдолг (внутренний + внешний), дефицит/профицит бюджета, ФНБ, размещения
ОФЗ, доходы от нефти и газа. Источники — `minfin.gov.ru` (открытые CSV/Excel), MOEX ISS API.

**Потребительская корзина (`fetch_russia_basket.py`).** Стоимость корзины по регионам, средние цены на товары, инфляция
по компонентам (продовольствие, непродовольственные, услуги). Источник — ЕМИСС.

**Биржа (`fetch_russia_market.py`).** IMOEX, RTS, MOEX Blue Chips; котировки SBER, GAZP, LKOH, ROSN, GMKN, YNDX;
доходности ОФЗ по срокам; курсы USD/RUB, EUR/RUB, CNY/RUB. Источник — **MOEX ISS API** (`iss.moex.com`), бесплатный,
открытый, JSON.

**Лента новостей (`fetch_russia_news.py`).** RSS-фиды Интерфакс, ТАСС, РБК, Коммерсантъ, Ведомости. Агрегация по
ключевым словам (ЦБ РФ, Минфин, SBER, нефть). Новости **разрешены**, потому что мы показываем ссылку на статью, а не
переписываем данные. Telegram и комментарии — нет.

**Сводка (`build_russia_summary.py`).** Собирает метрики по РФ в одну таблицу. Каждая — с пометкой источника. Контракт:

```python
{
    "metric": "inflation_yoy",
    "value": 8.5,
    "date": "2025-09-01",
    "source": "Росстат",
    "date_label": "сен 2025",
}
```

**Дополнительные инициативы.** Региональная разбивка корзины (карта), секторный анализ промышленности, сезонная
корректировка с пометкой «расчёт», экспорт отчётов, сравнение с ЕАЭС / Китаем / Турцией, тепловая карта инфляции, виджет
«итоги недели».

**Куда писать код.** `src/build_summary.py` уже большой и нагруженный. Логику по РФ — **в отдельный
** `src/russia/build_russia_summary.py`. Если очень нужно в основном — блок в самом низу с большим отступом и
разделителем-комментарием, но отдельный файл чище.

### Дизайн

Streamlit функционален, но не презентабелен. MVP должен выглядеть хорошо — задача команды: улучшить визуал. **Свобода
действий приветствуется**, но с сохранением работоспособности.

Направления, которые стоит рассмотреть:

- кастомная тема и CSS для Streamlit;
- карточки метрик вместо таблиц (сетка, значение, дата, источник);
- единый стиль графиков Plotly;
- карточки новостей с фильтром;
- аккуратная навигация (табы/секции);
- лёгкая иконографика.

Точных требований к цвету, шрифту и компоновке **нет** — команда сама решает, что смотрится лучше. Главное — чтобы
визуал подчёркивал достоверность источников (видно, откуда данные) и был презентабельным на защите. Тяжёлый JS, свои
фреймворки, анимации ради анимаций — не нужны, это замедлит работу.

### Как работать с LLM-ассистентом (тебе, LLM, — на заметку)

Команда использует ChatGPT Plus как помощника. Твоя задача — помогать, а не выдумывать.

- **Всегда проси показать релевантный код целиком**, прежде чем писать правки. Без контекста получится галлюцинация.
- **Формулировка задачи — узкая.** «Напиши функцию X для API Y по такому образцу ответа» — хорошо. «Улучши весь
  проект» — плохо.
- **Не выдумывай API.** Если не знаешь эндпоинт — попроси команду проверить руками (curl/браузер) и принести ответ.
- **Никогда не запрашивай и не принимай API-ключи** в промптах. Они живут в `.env`.
- **Предупреждай о рисках** парсинга: смена вёрстки, блокировки, лимиты.
- **Проверяй вместе с командой**: запрос → ответ → парсер → DataFrame → ячейка в дашборде.
- Если задача большая — **разбей на шаги**, предложи команде порядок.
- Если что-то неясно — **спроси**, не строй догадок.

### Что не надо

- Автотесты, Docker, CI — не приоритет на этом этапе.
- 16 других стран — только РФ.
- Свой backend — Streamlit + SQLite достаточно.
- Платные API — только бесплатные (MOEX, ЦБ, ЕМИСС).
- LLM для парсинга — только регулярки и BeautifulSoup.
- Агрегаторы без первоисточника — данные теряют достоверность.

### Координация

- Все изменения — через **PR в `main`**. Ветка → ревью у лидера проекта (он же backend) → merge.
- `app.py` — правит **один человек**, остальные через PR с описанием.
- Файлы в `src/russia/` — каждый правит свои.
- У всех локальные копии проекта — потеря данных маловероятна, но всё равно не пушить в `main` напрямую.

### Итог

**Источник важнее красоты и количества метрик.** 5 метрик из Росстата лучше 50 с левого сайта. **Отдельная логика —
отдельный файл**: `src/russia/build_russia_summary.py`, а не основной `build_summary.py`. **Дизайн — свобода**, но с
сохранением работоспособности: после правки `app.py` должен запускаться и рендерить таблицу.
