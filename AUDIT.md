# Macro Dashboard — результаты аудита и выводы

**Дата закрытия основного этапа: 26 октября 2026 года.** Проверялся **рабочий** проект Macro Dashboard. Основа: `Macro_dashboard — копия(3).zip`, последующие исправленные файлы, предоставленные владельцем логи и результаты `test.py`, скриншот сводной таблицы и выгрузки Excel/CSV/PDF.

**Заключение:** приложение **работоспособно**, но **не доказано, что всё работает без ошибок**. Локальный Streamlit, формат экспорта, операции хранения в проверенных сценариях и 53 из 59 шагов полного обновления успешно отработали. Часть внешних источников ответила ошибками. По этим причинам статус аудита — **«основная техническая проверка завершена, известные ограничения документированы»**, а не «100% источников исправны».

## 2. Исправления безопасности и надёжности

1. **Хранение SQLite (`src/storage.py`).** Контроль бизнес-ключей, атомарное объединение с существующей историей, откат при ошибке. Неполный ответ не должен стирать ранее сохранённые строки.
2. **Планировщик (`scheduler.py`).** Раздельные статусы `OK / EMPTY / PARTIAL / ERROR`, код возврата `0/1/2`, продолжение независимых шагов при отдельных отказах, маскирование типовых секретов в исключениях. Снимок и очистка выполняются только после полного успешного запуска без выбранной группы.
3. **FRED.** Контроль частичной загрузки стран и рядов, повторные попытки отдельных сетевых обращений; живой запуск четырёх этапов завершился успешно.
4. **Интерфейс.** Усилены экранирование HTML/PDF, защита экспортов Excel/CSV от формульных инъекций и безопасное отображение RSS. ForexFactory перенесён на ручную загрузку в интерфейсе, чтобы ошибка 403 не возникала на каждом обновлении страницы.
5. **Точечный парсер NBS.** Исправлен поиск китайского Core CPI на дополнительной странице архива; после изменения без записи извлечён верный период/значение.
6. **TLS ЦБ РФ.** Убраны прямые `verify=False` в пяти загрузчиках, для которых Windows подтвердил TLS с проверкой сертификата.
7. **Резервные файлы.** Подготовлен `.gitignore` с исключением локальных баз и резервных копий. **Отдельно проверить**, не были ли они ранее добавлены в индекс Git (`git ls-files`).

Технические исправления **не были основанием менять принятые методологии отношений к ВВП**. Патч, предлагавший сменить годовой долг США на иной WEO-ряд, **отвергнут и не должен устанавливаться**.

## 4. Методологические решения, которые не пересматривались

В ранее выполненной сверке источников были согласованы следующие подходы. Они сохранены в `SOURCES.md` и коде; текущий технический аудит **не является их независимым подтверждением**:

| Страна/метрика | Принятое решение / причина |
|---|---|
| Япония, долг | MOF Central Government за квартал; IMF General Government как годовая альтернатива. Не смешивать уровни. |
| Великобритания, долг | ONS General Government вместо методологически иного альтернативного ряда. |
| США, госфинансы | Учитывать разницу Federal Treasury и General Government BEA; помечать источник и период. |
| Китай, долг | NIFD для соответствующего квартального показателя, IMF годовой резерв; NIFD — исследовательский институт, не орган правительства. |
| Канада, бюджет | StatCan с пометкой NSA, если значение не сезонно скорректировано. |
| Сингапур, бюджет | При согласованных условиях годовой IMF вместо неподходящего квартального NSA ряда. |
| Индия, Турция, Бразилия, Япония, Корея | Точечный Bloomberg fallback для отдельных квартальных показателей при отсутствии рабочего официального ряда, с меткой `BBG`. |
| Австралия, Корея, Швейцария и др. | IMF WEO как годовой резерв с пометкой прогноза для текущего/будущего года. |
| Все страны | Не выдавать годовое за квартальное, расчётный ряд за прямую публикацию и данные одного уровня правительства за другой. |

Нельзя менять расчёты к ВВП по умолчанию: они прорабатывались отдельно. Новое изменение требует сравнения методологии, периодов и источников; «в агрегаторе другое число» само по себе не доказательство ошибки.

## 5. Заключение и дальнейшие действия

**Вердикт:** Macro Dashboard можно использовать как локальный рабочий инструмент **при контроле даты и происхождения каждого показателя**. Его основные модули не требуют масштабной переделки. При этом он **не гарантирует 100% успешное обновление всех источников** и не прошёл внешнюю независимую ревизию всех макрочисел.

Ближайшие действия — не новый полный аудит, а штатная эксплуатация: наблюдать за нестабильными источниками, сохранять резервные копии, проверять свежесть и итоговые статусы группы при обновлении. Особый приоритет для будущей безопасности — устранение узкого TLS-исключения, когда будет корректное доверие к сертификатам. Остальное — развитие функций по дорожной карте, **без повторного разбора уже согласованных формул**.

**Подтверждение владельцем при применении файлов:** после обновления исходников убедиться, что `git status` чист от приватных артефактов, `scheduler.py --dry-run` показывает ожидаемый состав и `quick_check` рабочей SQLite возвращает `ok`. Документация описывает состояние на дату аудита и не заменяет текущие журналы запуска.
